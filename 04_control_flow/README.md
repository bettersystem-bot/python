# 04 取消与超时控制

## 这一章学什么

真实异步程序不能只会“并发执行”，还必须会“及时停下来”。

这一章会讲：

- 任务取消是怎么发生的
- 超时为什么本质上常常伴随着取消
- `try` / `except` / `finally` 在异步里怎么配合
- 为什么 `CancelledError` 通常不应该被悄悄吞掉

## 为什么取消很重要

在真实业务里，任务经常需要提前结束：

- 请求超时了
- 用户断开连接了
- 已经拿到更快的结果了
- 服务准备关闭了

所以“取消”不是边角情况，而是异步程序的常态之一。

## 一个重要规则

遇到 `CancelledError` 时，通常应该这样处理：

- 先做必要清理
- 再把异常重新抛出去

这样调用方才能知道这个任务确实被取消了，整个调用链也更符合预期。

## Python 3.10 里的超时方式

在 `Python 3.10` 中，最常用的超时工具是 `asyncio.wait_for()`：

```python
await asyncio.wait_for(some_operation(), timeout=1.5)
```

如果超过超时时间，等待的协程通常会被取消，然后外层得到 `TimeoutError`。

## 运行方式

```bash
python3.10 04_control_flow/cancel_timeout.py
```

## 观察重点

你要特别注意：

- 超时发生时，任务内部有没有收到取消
- `finally` 有没有执行
- 调用方是如何感知取消结果的

## 练习建议

- 把超时时间缩短到更容易失败
- 把超时时间调长到足够成功
- 去掉 `raise` 看看会发生什么
- 在 `finally` 里再加一些资源释放逻辑
