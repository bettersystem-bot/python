# 05 常见异步模式

## 这一章学什么

这一章开始从“单个异步函数”走向“异步工作流”。

你会接触两个非常实用的模式：

- `asyncio.Queue`：生产者-消费者模型
- `asyncio.Semaphore`：并发数量限制

## `Queue` 解决什么问题

当一边负责生产任务，另一边负责处理任务时，`Queue` 非常适合做中间缓冲层。

典型场景：

- 批量抓取 URL
- 后台消费消息
- 上传任务排队处理
- 多个 worker 从同一个任务池取工作

## 为什么需要 `Semaphore`

很多人初学异步时，容易误以为“并发越多越好”。
实际上不受限制的并发常常是问题来源。

可能带来的后果：

- 打爆外部接口
- 占满系统资源
- 让整体调度变得混乱
- 内存压力变大

`Semaphore` 的作用，就是明确限制“同一时刻最多允许多少个任务进入关键区”。

## 运行方式

```bash
python3.10 05_patterns/queue_pipeline.py
```

## 观察重点

运行时请重点看：

- 生产者如何往队列里放任务
- worker 如何从队列取任务
- 为什么 worker 数量是 3，但同一时刻真正并发处理的只有 2 个
- 停止信号是如何让 worker 干净退出的

## 练习建议

- 修改 worker 数量
- 修改信号量大小
- 增加任务数量
- 把结果收集起来，而不仅仅是打印日志
