# 13 并发机制总览

## 这一章学什么

这一章先不急着写锁，而是先建立全局地图。

你会学到：

- 并发和并行的区别
- 线程、进程、协程分别解决什么问题
- GIL 为什么重要
- 为什么 I/O 密集和 CPU 密集要选不同工具

## 四种常见模型

### 线程 threading

线程像同一个办公室里的多个员工，共享同一份文件柜。

优点：

- 共享内存方便
- 适合阻塞 I/O
- 写法比异步更接近普通同步代码

缺点：

- 共享状态容易出错
- 需要锁保护
- 受 GIL 影响，不适合纯 Python CPU 密集并行

### 进程 multiprocessing

进程像不同办公室的员工，每个人有自己的文件柜。

优点：

- 可以利用多核 CPU
- 避开 GIL 对 CPU 并行的限制
- 隔离性更强

缺点：

- 进程间通信成本更高
- 数据需要序列化传递
- 启动开销比线程更大

### 协程 asyncio

协程像一个非常自觉的员工，遇到等待就主动让出座位。

优点：

- 非常适合大量 I/O 等待
- 单线程内也能处理很多任务
- 没有线程切换那么重

缺点：

- 需要整个调用链配合 `async` / `await`
- 不能直接跑阻塞函数
- CPU 密集任务会卡住事件循环

### 线程池 / 进程池 concurrent.futures

线程池和进程池像一个任务外包窗口。

你提交任务，池子负责复用工作线程或工作进程。

## 运行方式

```bash
python3.10 13_concurrency_overview/concurrency_map.py
```

## 观察重点

- I/O 等待型任务并发后耗时明显下降
- CPU 任务在不同模型下表现不同
- 选择模型前要先判断任务类型
