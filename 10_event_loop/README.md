# 10 事件循环与调试视角

## 这一章为什么要补

很多人学异步时会背 API，但一遇到卡顿、任务没执行、日志顺序奇怪，就不知道从哪里下手。

原因是：还没有真正从“事件循环”的角度看程序。

事件循环可以想象成一个餐厅大厅经理：

- 哪桌菜还在等后厨，就先不占服务员
- 哪桌菜好了，就通知服务员继续处理
- 哪个任务迟迟不让出服务员，整个大厅都会卡住

## 这一章学什么

你会学到：

- `get_running_loop()` 能看到什么
- `current_task()` 和 `all_tasks()` 如何帮助定位任务
- 为什么在协程里直接写阻塞代码会卡住事件循环
- `loop.set_debug(True)` 和 `slow_callback_duration` 如何辅助调试
- 如何用一个 heartbeat 判断事件循环是否健康

## 什么时候需要这种调试视角

这些场景尤其需要：

- 程序看起来“没报错但不动了”
- 并发任务明明创建了，却不知道是否还活着
- 某段代码让所有请求都变慢
- 想确认是不是有人阻塞了事件循环

## 运行方式

